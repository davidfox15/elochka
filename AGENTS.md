# AGENTS.md

## Назначение
- Этот документ задает рабочие правила для агентных инструментов в репозитории `elochka-camp`.
- Проект представляет собой статический сайт на Gulp 5 с шаблонизацией HTML и сборкой CSS/JS.
- Основные исходники лежат в `src/`, результат сборки попадает в `public/`.
- Папка `dest/` не используется как основной build-output в текущей конфигурации.

## Технологический стек
- Node.js + npm.
- Gulp 5 (CommonJS, `require`, `module.exports`).
- HTML partials через `gulp-file-include` с префиксом `@@`.
- CSS собирается в один минифицированный файл `public/styles/style.css`.
- JS минифицируется в `public/scripts/*.min.js` (если исходные скрипты есть).
- Оптимизация изображений: `gulp-imagemin`, `imagemin-jpeg-recompress`, `imagemin-pngquant`.
- BrowserSync для локальной разработки.

## Структура проекта
- `gulpfile.js` — оркестрация задач (`default`, `watch`, одиночные задачи).
- `tasks/*.js` — отдельные gulp-задачи.
- `src/pages/` — страницы и компоненты (`src/pages/components/`).
- `src/styles/` — CSS-файлы и переменные.
- `src/images/`, `src/fonts/`, `src/documents/`, `src/heic/` — ассеты.
- `public/` — артефакты сборки (генерируемая директория).

## Команды: установка и запуск
- Установка зависимостей: `npm install`.
- Полная сборка (production-like): `npx gulp`.
- То же через явную задачу: `npx gulp default`.
- Режим разработки с сервером и watch: `npx gulp watch`.
- Список доступных задач: `npx gulp --tasks-simple`.

## Команды: отдельные build-задачи
- Очистка `public/` (кроме `public/video`): `npx gulp clean`.
- Сборка HTML: `npx gulp html`.
- Сборка стилей: `npx gulp styles`.
- Минификация скриптов: `npx gulp scripts`.
- Конвертация HEIC в JPG: `npx gulp heic`.
- Удаление JPG, соответствующих HEIC: `npx gulp cleanheic`.

## Быстрые команды для агентов
- Проверка доступных gulp-задач: `npx gulp --tasks-simple`.
- Рекомендованный локальный smoke-check: `npx gulp clean && npx gulp`.
- Инкрементальная работа со стилями: `npx gulp styles`.
- Инкрементальная работа с шаблонами: `npx gulp html`.
- Проверка картинок после оптимизации: `npx gulp images` (если задача добавлена в будущем).

## Lint и форматирование (текущее состояние)
- В репозитории не настроены ESLint/Stylelint/Prettier-конфиги.
- npm-скрипт `test` сейчас заглушка и всегда падает (`Error: no test specified`).
- Перед коммитом делайте минимум ручную проверку:
- `npx gulp clean && npx gulp`.
- `npx gulp watch` и визуальная проверка страниц в браузере.

## Тесты (текущее состояние и единичный тест)
- Автоматических unit/integration/e2e тестов в репозитории сейчас нет.
- Команды запуска single test отсутствуют до внедрения тестового раннера.
- Если добавляете тестовую инфраструктуру, предпочтителен встроенный Node test runner.
- Пример запуска всех тестов после внедрения: `node --test`.
- Пример запуска одного тест-файла: `node --test path/to/file.test.js`.
- Пример запуска одного теста по имени: `node --test --test-name-pattern="should ..."`.

## Правила для изменения кода
- Сначала меняйте исходники в `src/`, не редактируйте вручную артефакты в `public/`.
- После изменений в шаблонах/стилях/тасках всегда прогоняйте сборку.
- Не переименовывайте gulp-задачи без обновления `gulpfile.js` и документации.
- Сохраняйте совместимость с CommonJS в build-скриптах (`tasks/*.js`, `gulpfile.js`).
- Избегайте внедрения новых инструментов без явной необходимости проекта.

## Импорты и модули (Node/Gulp код)
- Используйте `const` для импортов: `const x = require("pkg")`.
- Группируйте импорты в начале файла: сначала core (`fs`, `path`), затем внешние, затем локальные.
- Экспортируйте одну задачу через `module.exports = fn` или объектом при нескольких функциях.
- Предпочитайте маленькие, одноответственные gulp-задачи.
- Имена функций задач — глаголы/действия: `clean`, `styles`, `convertHEIC`.

## Форматирование и стиль
- Следуйте текущему стилю: 2 пробела, двойные кавычки, завершающая `;`.
- Сохраняйте trailing comma там, где он уже используется в многострочных литералах.
- Не смешивайте стили форматирования в одном файле.
- Избегайте длинных строк без необходимости; переносите цепочки `.pipe(...)` построчно.
- Комментарии оставляйте только для неочевидной логики.

## Типы и контракты
- Проект без TypeScript; добавлять TS только при отдельной договоренности.
- Для JS-функций поддерживайте явные входы/выходы и стабильные сигнатуры.
- В async-функциях всегда учитывайте сценарии пустых коллекций и отсутствующих файлов.
- Если функция может вернуть `undefined`, учитывайте это в вызывающем коде.

## Нейминг
- JS: `camelCase` для переменных и функций.
- Константы-конфиги: `UPPER_SNAKE_CASE` только при реальной константности и переиспользовании.
- CSS-классы: kebab-case (например, `main-social-text`, `promo-mobile-img`).
- CSS-переменные: `--kebab-case` с тематическими префиксами (`--color-*`, `--font-*`, `--br-*`).
- Файлы задач в `tasks/`: короткие существительные/глаголы (`images.js`, `styles.js`).

## HTML и шаблоны
- Для переиспользуемых блоков применяйте `@@include` и `@@loop`.
- Компоненты храните в `src/pages/components/`.
- Страницы верхнего уровня — в `src/pages/*.html`.
- Проверяйте валидность относительных путей до ассетов после сборки в `public/`.
- Поддерживайте семантичную структуру (`main`, `section`, заголовки по иерархии).

## CSS и UI
- Общие токены держите в `src/styles/variables.css`.
- Базовые reset/typography/layout — в `src/styles/global.css`.
- Страничные стили раскладывайте по отдельным файлам (`main.css`, `details.css`, и т.д.).
- Учитывайте адаптивность: в проекте активно используются media queries на `768px`.
- При добавлении новых цветов/размеров сначала проверяйте, можно ли переиспользовать существующие CSS-переменные.

## Обработка ошибок
- В Node-задачах оборачивайте файловые операции в `try/catch`.
- Для ожидаемых ситуаций (нет файла, пустая папка) логируйте понятное сообщение без падения пайплайна.
- Для неожиданных ошибок логируйте `error.message` и контекст операции.
- Не скрывайте критические ошибки, если они делают артефакты некорректными.

## Работа с ассетами
- Исходные изображения храните в `src/images/` (или `src/heic/` до конвертации).
- Конвертацию HEIC запускайте отдельно перед основной сборкой при необходимости.
- Не коммитьте временные/локальные артефакты, не влияющие на финальную выдачу.
- Проверяйте, что тяжелые изображения действительно оптимизируются пайплайном.

## Проверка перед PR
- Выполнить: `npm install` (если свежий checkout).
- Выполнить: `npx gulp clean && npx gulp`.
- Выполнить: `npx gulp watch` и проверить ключевые страницы (`index.html`, `smena.html`, `details.html`).
- Проверить, что ссылки, изображения, шрифты и документы открываются из `public/`.
- Убедиться, что не добавлены секреты и лишние бинарные файлы.

## Git и коммиты
- Делайте небольшие тематические коммиты.
- Сообщение коммита: короткий imperative, затем при необходимости деталь в теле.
- Не смешивайте рефакторинг и функциональные изменения без причины.
- Не редактируйте lockfile вручную; он меняется только инструментами npm.

## Ограничения и ожидания
- Не добавляйте новые зависимости для линтинга/тестов без явного запроса владельца.
- Не переносите проект на TS/ESM в рамках локальных правок контента или стилей.
- В задачах сборки избегайте silent-fail: ошибка должна быть видна в консоли.
- Любые изменения пайплайна (`tasks/*.js`, `gulpfile.js`) сопровождайте проверкой `npx gulp`.
- Если в PR есть только контент/разметка, не трогайте инфраструктурные файлы без причины.

## Краткий чеклист для агентов
- Понять, затрагивает ли изменение `src/`, `tasks/` или оба слоя.
- Внести минимально достаточные правки без лишних перестроений архитектуры.
- Прогнать релевантные gulp-задачи и зафиксировать результат.
- Проверить итог в `public/` и только затем готовить изменение к ревью.
